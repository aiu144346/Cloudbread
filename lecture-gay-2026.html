MODULE 1. 프롬프트 3대 제어 체계의 구조적 이해

Ask anything, @ to mention, @ to action, / for actions

┌─────────────────────────────────────────────────────────────────────────┐
│                            Chat Input Box                               │
│         "Ask anything, @ to mention, / for actions..."                  │
└──────────────┬──────────────────────────────────────────┬───────────────┘
               │                                          │
         [@ 키 입력]                                 [/ 키 입력]
         ┌─────┴──────────────────────┐                   │
         ▼                            ▼                   ▼
  [@ to mention]               [@ to action]       [/ for actions]
  (어떤 정보를 볼 것인가)        (누가/무엇으로 행할 것인가) (어떤 방식으로 실행할 것인가)
  · 파일 / 폴더 (@src/...)      · 전문 서브에이전트 호출   · /plan (단계별 기획)
  · 코드 심볼 (@UserService)    · @research / @browser    · /goal (끝까지 자율 실행)
  · 터미널 로그 (@terminal)     · @image-generator        · /grill-me (인터뷰형 설계)
  · Git 변경분 (@git:diff)      · @firestore-rules-author · /teamwork (다중 에이전트)
  · 프로젝트 규칙 (@rule:...)   · @ai-architect 등        · /automation (정기 스케줄)
  · 이전 대화 (@conversation)   · @mcp:<서버명> 직접 지정  · /boost (고난도 심층 추론)
🎯 @ to mention (시야 고정)

전체 코드베이스를 탐색하느라 토큰과 시간을 낭비하지 않도록 특정 파일, 심볼(함수/클래스), 터미널 로그, 규칙에 에이전트 시야를 즉시 고정합니다.

🤖 @ to action (주체/도구 위임)

일반 대화를 넘어 읽기 전용 조사관(@research), 내장 브라우저(@browser), 이미지 생성기, 또는 외부 MCP 서버에 실행 권한을 직접 위임합니다.

⚡ / for actions (모드 전환)

사전 계획서 작성(/plan), 역질문 인터뷰(/grill-me), 무중단 완수(/goal), 다중 에이전트 협업(/teamwork) 등 실행 루프를 전환합니다.

📌 1. @ to mention : 8대 정밀 컨텍스트 주입 레퍼런스

멘션 대상 입력 예시 핵심 기능 및 활용 팁
Files (파일)@src/auth/token.py지정한 파일 전체 코드를 즉시 로드합니다. 일부 글자만 쳐도 퍼지 검색으로 자동완성됩니다.
Folders (폴더)@src/components/폴더 트리 구조와 모듈 인터페이스 요약을 주입해 아키텍처를 파악하게 합니다.
Code Symbols (심볼)@validate_token, @UserService어느 파일에 있는지 몰라도 함수·클래스 이름만으로 정확히 타겟팅합니다.
Terminal (터미널)@terminal최근 터미널 stdout/stderr 및 에러 스택 트레이스를 드래그 복사 없이 1초 만에 주입합니다.
Git Context@git:diff, @git:staged현재 수정 사항을 로드하여 셀프 코드 리뷰, 커밋 메시지, PR 본문 작성에 활용합니다.
Rules (규칙)@rule:clean-architecture.agents/rules/ 또는 GEMINI.md에 정의된 프로젝트 규칙을 이번 턴에 강제 적용합니다.
Past Conversations@conversation:<id>이전 대화 세션의 결정 사항과 해결 맥락을 현재 대화로 끌어와 이어서 작업합니다.
Web & Docs@web:https://...공식 문서나 최신 API 레퍼런스 URL을 지정하여 최신 스펙 기준으로 코딩하게 합니다.

⚡ 2. / for actions 슬래시 커맨드 & 2026-2.32.1 6대 최신 기능

명령어 / 신기능 핵심 동작 실전 활용 포인트
/plan코드 작성 전 상세 실행 계획서(Artifact)를 먼저 작성하고 검토받음대규모 리팩토링, 아키텍처 변경 전 필수

/teamwork (Swarm)공유 메시지 보드 기반 다중 에이전트(UI/데이터/차트/검수) 병렬 협업반응형 웹페이지 및 인터랙티브 대시보드 풀스택 구축
/automation (신규)5단계 마법사로 타임존(CRON_TZ) 기반 정기 백그라운드 에이전트 생성매일 아침 9시 PR 체크, 주간 프로젝트 요약 보고서 자동화
run_workflow (신규)Python 스크립트로 agent(), parallel(), pipeline() 대규모 제어수십 개 소스 파일 동시 보안 감사 및 일괄 마이그레이션
Generative UI (신규)채팅창 내부에 즉시 조작 가능한 HTML/Tailwind 위젯(<agent-embed>) 렌더링실시간 예산/비용 시뮬레이터, 인터랙티브 차트 설명
hooks.json (신규)PreToolUse, PostToolUse, Stop 등 6대 생명주기 이벤트 제어위험 명령어 차단, 코드 수정 직후 자동 Linter 실행 강제
/learn & /boost해결 노하우를 .agents/rules/에 영구 저장(/learn) / 심층 추론(/boost)팀 컨벤션 자산화 및 고난도 동시성/성능 버그 해결
MODULE 3 & 7. 왜 에이전트 1명 대신 Swarm(/teamwork)으로 웹과 대시보드를 만드나요?

🍳 "1인 푸드트럭" vs "4인 전문 셰프 레스토랑 주방"

에이전트 1명에게 데이터 100건 생성 + 다차원 필터 계산 + 4종 차트 렌더링 + 반응형 UI 디자인을 한꺼번에 시키면, 뒤로 갈수록 앞선 변수명을 잊어버려 차트가 빈 화면으로 뜨거나 디자인을 고치다 계산 로직을 망가뜨립니다. 반면 Native Swarm(/teamwork)은 전문 역할을 나눈 4명의 워커가 독립된 작업 공간(workspace: "share")에서 자기 전담 파일만 동시에 작성합니다.

ROLE 1 · 데이터 & 통계 엔진
🗄️ data-architect
전담: data.js

보드의 #1번 데이터 스키마 계약에 맞춰 120건의 현실적인 데이터셋과 다중 필터·집계 함수를 완벽히 구현합니다.

ROLE 2 · 레이아웃 & KPI 카드
🎛️ dashboard-ui
전담: index.html, dashboard.css

상단 멀티 필터 바, 4대 핵심 KPI 요약 카드, 2×2 차트 그리드, 상세 피드백 테이블 UI를 반응형으로 구축합니다.

ROLE 3 · 인터랙티브 차트
📈 chart-visualizer
전담: charts.js, app.js

필터 변경 시 0.1초 만에 동시 갱신되는 막대·그룹바·도넛·추이 차트와 엑셀 호환 CSV 다운로드 기능을 연결합니다.

ROLE 4 · 교차 검증 검수관
🕵️ qa-verifier
직접 파일 수정 절대 금지!

필터 선택 시 KPI 숫자와 차트 합계가 일치하는지, 0건 검색 시 NaN 에러가 없는지 검수하여 담당 워커에게 수정을 지시합니다.
