# Google Antigravity(AGY) 심화 활용 가이드: `@ to mention`, `@ to action`, `/ for actions` 완벽 정리

Google Antigravity(AGY)의 프롬프트 인터페이스에 표기되는 안내 문구(`Ask anything, @ to mention, / for actions` 및 `@ to mention`, `@ to action`)는 에이전트에게 전달할 **컨텍스트(맥락)를 정밀 타겟팅**하고, **특정 행동(Action)이나 전문 에이전트/도구를 즉각 발동**시키는 핵심 조작 체계입니다.

Antigravity 심화 활용을 위해 `@ to mention`(컨텍스트 주입), `@ to action`(실행 주체/도구 바인딩), 그리고 이와 긴밀히 연동되는 `/ for actions`(슬래시 워크플로우 커맨드)의 체계를 정리해 드리겠습니다.

---

## 1. 구조적 이해: Mention과 Action의 차이

```text
┌─────────────────────────────────────────────────────────────┐
│                      Chat Input Box                         │
│  "Ask anything, @ to mention, / for actions..."             │
└──────────────┬──────────────────────────────┬───────────────┘
               │                              │
         [@ 키 입력]                     [/ 키 입력]
         ┌─────┴──────────────┐               │
         ▼                    ▼               ▼
  [@ to mention]       [@ to action]     [/ for actions]
  (어떤 정보를 볼 것인가)  (누가/무엇으로 행할 것인가) (어떤 방식으로 실행할 것인가)
  · 파일 / 폴더        · 전문 서브에이전트      · /plan (단계별 기획)
  · 코드 심볼 (함수/클래스)· MCP 도구 직접 지정    · /goal (끝까지 자율 실행)
  · 터미널 출력 로그    · 브라우저 제어         · /grill-me (인터뷰형 설계)
  · Git Diff / 커밋   · 특정 커스텀 Agent     · /teamwork (다중 에이전트)
  · 규칙(Rules)                               · /compact (컨텍스트 압축)
```

* **`@ to mention` (Context Targeting)**:
  전체 코드베이스를 무작정 탐색하느라 토큰과 시간을 낭비하지 않도록, 에이전트의 시야를 특정 파일, 심볼, 로그, 규칙에 즉시 고정합니다.
* **`@ to action` (Delegation & Tool Binding)**:
  일반 LLM 대화를 넘어, 특정 작업에 특화된 서브에이전트(Subagent)나 외부 MCP(Model Context Protocol) 도구에게 실행 권한을 직접 위임합니다.
* **`/ for actions` (Workflow Triggers)**:
  자율 에이전트의 행동 모드(계획형, 인터뷰형, 야간 목표 완수형 등)를 전환하는 상위 제어 명령입니다.

## 2. `@ to mention` : 정밀 컨텍스트 주입

프롬프트 입력창에서 `@`를 입력하면 자동완성 드롭다운이 열리며 아래 항목들을 멘션할 수 있습니다.

| 멘션 대상 | 입력 예시 | 기능 및 활용법 |
| :--- | :--- | :--- |
| **Files (파일)** | `@src/auth/token.py` | 지정한 파일의 전체 코드를 프롬프트 컨텍스트에 즉시 로드합니다. 경로 일부만 타이핑해도 퍼지 검색(Fuzzy Search)으로 자동완성됩니다. |
| **Folders (디렉토리)** | `@src/components/` | 해당 디렉토리의 파일 트리 구조 및 인터페이스 요약 정보를 에이전트에게 주입하여 모듈 전체 구조를 파악하게 합니다. |
| **Code Symbols (심볼)** | `@validate_token`, `@UserService` | 프로젝트 전체에서 색인(Index)된 함수, 클래스, 인터페이스, 메서드를 직접 멘션합니다. 파일 위치를 몰라도 심볼명만으로 정확히 타겟팅됩니다. |
| **Terminal (터미널)** | `@terminal` 또는 `@terminal:last-output` | 최근 실행된 터미널 명령의 `stdout`/`stderr` 및 에러 스택 트레이스를 컨텍스트로 전달합니다. 컴파일 에러나 테스트 실패 해결 시 필수적입니다. |
| **Git Context** | `@git:diff`, `@git:staged` | 현재 작업 트리의 수정 사항(Uncommitted changes)이나 최근 커밋 이력을 프롬프트에 로드하여 코드 리뷰나 PR 설명을 작성할 때 사용합니다. |
| **Rules (지침/규칙)** | `@rule:style-guide`, `@rule:security` | `.agents/rules/` 또는 설정에 정의된 특정 프로젝트 룰을 에이전트가 이번 턴에서 엄격하게 준수하도록 강제 로드합니다. |
| **Past Conversations** | `@conversation:<id>` | 이전 대화 세션의 작업 맥락, 결정 사항, 해결 과정을 현재 대화로 끌어와 이어 작업합니다. |
| **Web & Docs (웹/문서)** | `@web:https://...` | 공식 기술 문서나 외부 API 레퍼런스를 지정하여 에이전트가 최신 문서를 기반으로 작업하도록 유도합니다. |

## 3. `@ to action` : 행동 주체 및 도구 위임

`@`는 컨텍스트를 읽는 것을 넘어, 에이전트의 행동(Action)을 특정 주체나 도구에 바인딩할 때도 사용됩니다.

### (1) Subagent(서브에이전트) 직접 지정 호출
* **`@researcher`**: 코드 작성이나 파일 수정을 하지 않는 읽기 전용 조사 에이전트를 구동합니다. 대규모 코드베이스 분석이나 레퍼런스 조사를 컨텍스트 오염 없이 격리 수행합니다.
* **`@browser`**: Antigravity 내장 헤드리스/유저 Chrome 브라우저 에이전트를 호출하여 로컬 웹서버 테스트, UI 렌더링 검증, 콘솔 에러 캡처 액션을 수행합니다.
* **`@image-generator`**: UI 목업, 다이어그램, 그래픽 에셋 생성을 전담하는 서브에이전트에게 작업을 위임합니다.
* **`@custom-agent:<name>`**: 사용자가 `.agents/agents/`에 정의한 커스텀 에이전트(예: `@db-migrator`, `@code-reviewer`)를 직접 지정하여 작업을 실행합니다.

### (2) MCP Tools(도구) 명시적 트리거
* **`@mcp:<server_name>`**: 연결된 Model Context Protocol 서버(예: GitHub, PostgreSQL, Biomolecular Viewer 등)의 도구를 지정하여 에이전트가 해당 외부 액션을 우선 사용하도록 지시합니다.

## 4. 연계 학습: `/ for actions` (슬래시 커맨드)

프롬프트 창에 `/`를 입력했을 때 실행되는 액션 모드로, `@` 멘션과 결합할 때 강력한 시너지를 냅니다.

| 슬래시 명령어 | 핵심 기능 | 심화 활용 팁 |
| :--- | :--- | :--- |
| **`/plan`** | 코드 작성 전 상세 실행 계획서(Artifact)를 먼저 작성하고 사용자 검토를 받습니다. | 대규모 리팩토링이나 아키텍처 변경 전 필수. |
| **`/goal`** | 목표가 완전히 달성(빌드 통과, 테스트 성공 등)될 때까지 중단 없이 자율 루프를 돕니다. | 야간 작업이나 긴 빌드/테스트 파이프라인 디버깅 시 유용. |
| **`/grill-me`** | 에이전트가 개발자에게 역질문(인터뷰)을 던져 요구사항의 모호함을 해소합니다. | 기획 단계에서 엣지 케이스와 인터페이스 사양을 확정할 때 추천. |
| **`/browser`** | 로컬 웹 애플리케이션의 E2E 테스트, 콘솔 에러 추적, UI 인터랙션을 브라우저에서 직접 검증합니다. | 프론트엔드 작업 후 실제 브라우저 동작 확인 시 실행. |
| **`/teamwork`** | 여러 서브에이전트들이 역할을 분담(기획, 백엔드, 프론트엔드, QA)하여 병렬로 협업합니다. | 풀스택 신규 기능 구현에 적합. |
| **`/compact`** | 대화가 길어져 컨텍스트 창이 찰 때, 핵심 상태와 결정 사항만 요약하여 토큰을 정리합니다. | 긴 세션의 반응 속도와 정확도를 복구할 때 사용. |
| **`/learn`** | 방금 해결한 복잡한 디버깅이나 문제 해결 방식을 영구 스킬/규칙(`.agents/rules/`)으로 자동 저장합니다. | 동일한 실수를 방지하고 팀 컨벤션을 내재화할 때 사용. |
| **`/boost`** | 깊은 추론(Deep Thinking)과 다각도 검증을 거치는 고난도 문제 해결 모드를 작동시킵니다. | 까다로운 알고리즘, 동시성 버그, 성능 병목 해결에 사용. |
| **`/schedule`** | 주기적으로 실행될 크론(Cron) 작업이나 지연 타이머를 설정합니다. | 매일 아침 테스트 실행 및 모니터링 자동화에 사용. |
| **`/btw`** | 현재 진행 중인 메인 태스크의 컨텍스트를 어지럽히지 않고 가벼운 곁가지 질문을 던집니다. | 작업 도중 사소한 문법이나 개념 질문 시 활용. |

## 5. 심화 실전 조합 시나리오 (Best Practices)

멘션(`@`)과 액션(`/`)을 함께 조합하여 사용하는 대표 패턴입니다.

### 패턴 A: 터미널 에러 즉시 해결
```text
@terminal @src/api/auth.ts /plan
방금 발생한 토큰 만료 에러의 원인을 분석하고, 안전한 갱신 로직을 구현하는 계획을 세워줘.
```
* **효과**: `@terminal`로 에러 로그를 주입하고, `@src/api/auth.ts`로 관련 파일만 명시한 뒤, `/plan`을 통해 성급한 코드 수정 없이 단계별 계획부터 수립합니다.

### 패턴 B: 아키텍처 규칙을 준수하는 리팩토링
```text
@rule:clean-architecture @UserService /grill-me
UserService 클래스를 도메인/인프라 계층으로 분리하려고 해. 필요한 요구사항을 나에게 인터뷰해줘.
```
* **효과**: 아키텍처 규칙을 강제 적용하고, 특정 클래스 심볼을 타겟팅한 후, `/grill-me` 인터뷰 모드로 설계 누락을 방지합니다.

### 패턴 C: 야간 자율 테스트 통과 (End-to-End 완수)
```text
@tests/e2e/checkout.spec.ts /goal
결제 플로우 E2E 테스트가 모두 통과할 때까지 백엔드 API와 프론트엔드 유효성 검증 로직을 수정하고 검증을 완수해줘.
```
* **효과**: 테스트 파일을 타겟팅하고 `/goal` 모드를 걸어두면 에이전트가 **"코드 수정 ➔ 테스트 실행 ➔ 에러 분석 ➔ 재수정"** 루프를 통과할 때까지 자율적으로 반복합니다.
