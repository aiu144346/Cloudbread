## 🧭 실습 전 1분 핵심 요약: Swarm이 웹페이지와 대시보드를 완벽하게 만드는 원리

```text
[수강생 (/teamwork 입력)]
        │
        ▼
[🧑‍💼 Coordinator (총괄 PM)] ──👉 1단계: 공유 보드(#1)에 'DOM ID 규격' 및 'JSON 데이터 스키마' 선공지!
        │
        ├──👉 [🎨 워커 1: 레이아웃/UI 전담]   (workspace: "share" ➔ index.html, style.css)
        ├──👉 [🗄️ 워커 2: 데이터/통계 전담]   (workspace: "share" ➔ data.js, calculator.js)
        ├──👉 [📈 워커 3: 차트/인터랙션 전담] (workspace: "share" ➔ charts.js, app.js)
        │
        ▼ (워커 1~3 작업 완료 후 보드에 #번호 보고)
[🕵️ 워커 4: QA 검수관 (verifier)] ──👉 직접 코드 수정 금지! 통합 작동·수치 일치 검증 후 버그 발견 시 @담당워커 호출
```

1. **파일 충돌 0% (`workspace: "share"` + 파일 전담제)**: 각 에이전트가 자기만의 작업 복사본(`share`)에서 서로 다른 파일(`index.html` vs `data.js` vs `charts.js`)만 작성하므로 코드가 뒤엉키지 않습니다.
2. **스키마 선공지 계약 (`Schema Contract`)**: 총괄 PM이 데이터 필드명과 HTML ID를 보드 `#1`번 글에 먼저 못 박고 시작하므로, 차트가 빈 화면으로 뜨는 버그가 원천 차단됩니다.
3. **검수관(`verifier`)의 교차 검증**: 마지막에 검수 전담 에이전트가 *"필터를 바꿨을 때 KPI 합계 숫자와 차트 숫자가 똑같은지"*, *"콘솔 에러는 없는지"*를 확인한 뒤 완성본을 전달합니다.

```text

- 과정명: [2026 공공기관 AI 에이전트 & 바이브 코딩 실무 마스터 과정]

[2. Swarm 워커 역할 및 파일 소유권(File Ownership) 분담]
파일 충돌이 절대 발생하지 않도록 각 워커에게 독립 워크스페이스(workspace: "share")를 부여하고 담당 파일을 엄격히 분리해줘:

1) `layout-designer` (전담 파일: `index.html`, `styles.css`)
   - 상단 고정 네비게이션 바, 히어로 배너(핵심 카피 + 모집 마감 카운트다운 영역 + '수강신청 바로가기' CTA 버튼)

   - `app.js`와 연결할 DOM 요소의 `id`와 `data-*` 속성 규격을 보드(#1)에 먼저 공유할 것

2) `interaction-dev` (전담 파일: `app.js`)
   - `layout-designer`가 공유한 DOM ID 규격에 맞춰 순수 JavaScript 인터랙션 구현
   - 기능 1: 모집 마감일까지 남은 시간 실시간 카운트다운 타이머
   - 기능 2: 커리큘럼 주차별 탭 클릭 시 부드러운 콘텐츠 전환 및 FAQ 아코디언 열기/닫기
   - 기능 3: 수강신청 폼 실시간 유효성 검증(빈칸, 이메일/전화번호 형식 체크) 및 제출 시 신청자 정보를 요약 보여주는 축하 모달 팝업 + 로컬스토리지 신청 내역 저장

3) `qa-verifier` (전담: 통합 검수 및 브라우저 테스트, 직접 파일 수정 금지)
   - 두 워커의 작업이 끝나면 HTML과 JS의 ID/클래스 바인딩이 정확히 일치하는지, 콘솔 에러가 없는지 검수
   - 문제가 발견되면 직접 수정하지 말고 보드에서 `@layout-designer` 또는 `@interaction-dev`를 멘션해 수정시킬 것

모든 검수가 완료되면 내 메인 워크스페이스에 파일들을 병합하고, 완성된 페이지 주요 기능과 Swarm 보드 링크를 안내해줘.
```

```text
첨부(멘션)한 데이터 파일의 실제 컬럼 구조와 데이터 성격을 먼저 분석한 뒤, 이 데이터를 가장 효과적으로 탐색하고 시각화할 수 있는 맞춤형 인터랙티브 대시보드 웹앱을 3인조 Swarm으로 만들어줘:

2. `ui-chart-builder` (workspace: "share"): 카테고리 컬럼은 상단 멀티 필터로, 수치형 컬럼은 4대 KPI 카드와 비교 막대/추이 차트로, 전체 로우는 검색 가능한 테이블로 자동 매핑하여 구현
3. `verifier` (workspace: "inherit"): 원본 파일의 총 건수 및 합계 수치가 대시보드 화면의 수치와 100% 일치하는지 대조 검수 후 병합
```

# Part C. 🎮 [Swarm 실시간 지휘 & 커스터마이징 키트] 웹/대시보드 제작 중 복사해서 쓰는 6줄 명령어

Swarm이 웹페이지나 대시보드를 만들고 있는 도중, 또는 완성 직후에 원하는 대로 수정·검증하는 한 줄 명령어입니다.

### 🎮 지휘 C-1. 현재 워커들의 작업 진행률 표로 브리핑받기
```text
지금 Swarm 보드 현황(status)을 확인해서 각 워커가 어떤 파일을 완료했고 누가 작업 중인지 표로 요약해줘.
```

### 🎮 지휘 C-2. 내장 브라우저를 띄워 완성된 웹페이지/대시보드 자동 클릭 테스트하기 (`@browser`)
```text
@browser 에이전트를 띄워서 방금 Swarm이 만든 index.html을 열고, 상단 필터와 탭 버튼을 하나씩 클릭해보며 차트와 화면이 에러 없이 잘 바뀌는지 스크린샷과 함께 검증해줘.
```

### 🎮 지휘 C-3. 데이터/차트 코드는 건드리지 않고 UI 컬러 테마만 핀셋 변경하기
```text
@dashboard-ui (또는 UI 담당 워커)에게만 지시해서, 데이터나 차트 로직은 그대로 두고 전체 디자인 테마를 화이트&블루 계열의 밝은 보고서 인쇄용 스타일로 변경해달라고 보드에 전달해줘.
```

### 🎮 지휘 C-4. 대시보드에 새로운 차트나 엑셀 다운로드 버튼만 추가시키기
```text
@chart-visualizer 워커에게 현재 대시보드 우측 상단에 [현재 화면 인쇄 / PDF 저장] 버튼과 상위 Top 5 항목만 하이라이트해서 보여주는 랭킹 카드를 추가해달라고 보드에 지시해줘.
```

### 🎮 지휘 C-5. 모델 쿼터(Quota) 부족으로 멈춘 워커 맥락 유지한 채 깨우기
```text
혹시 모델 쿼터가 소진되어 멈춘 워커가 있다면, 삭제(kill)하지 말고 내 현재 모델로 전환(swarm model)해서 기존 맥락 그대로 이어서 작업하게 해줘.
```

### 🎮 지휘 C-6. 최종 결과물 워크스페이스 병합 확인 후 모든 워커 안전 퇴근시키기
```text
결과물이 완벽해! 각 워커의 작업물을 내 메인 워크스페이스에 최종 반영했는지 확인하고, 실행 중인 모든 Swarm 워커들을 안전하게 종료(kill)해줘.
```
